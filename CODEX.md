# Berkeley Food Savings App

## Purpose

Build a Berkeley student food savings app.

Goal:
Help students answer:
"What is the cheapest good meal I can get right now?"

---

## Working Style

This project is for learning software engineering and system design.

Prioritize understanding over speed.

Before implementing major features:
- Explain the design
- Discuss tradeoffs
- Confirm the approach

Do not generate major architecture without discussion.

---

## Architecture Ownership

I want to personally understand and design:
- System architecture
- Database schema
- API structure
- Data flow
- Infrastructure decisions

Help me reason through these decisions.

---

## Coding Guidelines

Good candidates for AI implementation:
- UI components
- Styling
- Small utilities
- Tests
- Boilerplate

Do not blindly implement:
- Database architecture
- Service boundaries
- Core application structure

---

## Development Approach

Follow:

1. Discuss
2. Design
3. Implement
4. Review

Avoid:
- Overengineering
- Premature optimization
- Adding technologies without a reason

---

## Documentation

docs/architecture

Read relevant documents when making changes.
